⚠️ Requirements

{% if courier_mode %}
  • One row per store / receiver, with its address. The columns are found by their headers, as in Generate Labels: "Store Name", "Receiver Name", "Attn", "Address 1", "Address 2", "Address 3", "Suburb", "State", "Postcode" and "Country". A whole address in one column works too. Columns that describe the store ("Store Type", "Store Size") aren't its name.
  • Header Row: Tell the tool which row holds those headers (e.g. 7).
  • Pack columns: one per pack group, headed 1, 2, 3 … (or P1, P2 …). Each store's cell holds that pack's Packing Spec, e.g. OB600100100, CS1070580140, Box, or 2 x OB600100100 for two boxes.
  • x or X (or a blank cell) under a pack: that store doesn't get that pack, so it isn't counted for it.
  • Not pack columns: numbered columns that hold only numbers (item quantities), and a number heading several columns at once (a merged cell over a pack's items).
  • Item Reference: T + the tab + P + the pack's number, then the store, e.g. T1P2 Corio Village = pack 2 of the first selected tab for Corio Village; T2P1 … = pack 1 of the second tab.
  • Names: "Store Name" (or "Store", "Retailer") names the store and goes in the Item Reference; "Receiver Name" (or "Receiver", "Consignee", "Ship To") is who the courier delivers to; "Attn" is the person to attend. They can be the same or different. No Receiver Name: the store receives it. No Store Name: the receiver's name stands in for it.
  • Consignment Reference: the job (J + 6 digits) found above the header row, e.g. J466307 from J466307-11; type it in if there's none.
  • Output: only the courier CSV (Open360, OpenFreight or both), in a new project folder with the Excel file. No packing labels.
  • Names only: a list with store names and no address columns still works: addresses come from the address book, or you pick or type them in the consignment table.
{% elif horizontal_mode %}
  • The Packing Sheets layout: one row per store, one column per item, each pack's items under one merged header in the pack row, and the job numbers in a row above the stores.
  • Packing-sheet codes: the "Code for Pack …" columns Packing Sheets puts at the start of each pack are read like any header: each store's cell holds its code. Sub-group codes ("Code for pack 1: 1-5") sort the labels within a code. No code column? The codes are taken from the Signature Links file, else worked out exactly as Packing Sheets does.
  • Signature Links file (optional): the one Packing Sheets made for this job. Its Label Plugin tab fills in the tabs and header rows for you, and its codes group the labels (checked against the quantities: a difference is a warning). The dividers have no barcodes: every item on the labels has its own.
  • Header Row: the row just above the first store (filled in from the Label Plugin when there is one).
  • Packing Spec: a column per pack headed with the pack's number (1, 2, 3 …), each store's spec in it (OB600100100, 2 x CS450320150, x for none), as in Courier Import; or the stock columns named in the Label Plugin.
  • Order: pack by pack as on the packing sheets, an audit page before each pack, then code A, B, C … with a divider before each, stores in sheet order.
  • Item Reference: the store's number in its tab, T + the tab, P + the pack, then the store: 03T1P2 Chadstone.
{% else %}
  • Header Row: Tell the tool which row holds your headers (e.g. 1 or 2). It finds the columns automatically.
  • Required Columns: "Packing Spec", "Job Number" and "Install" must be present.
  • Packing Spec: Merge the Packing Spec cells across all rows that go in the same box. Every row needs a Packing Spec.
  • Job Number: Every row needs one.
  • Install: Y for a box going to an installer; N or blank for a box going to the store. All rows of one box must agree.
  • Address: All rows of one box must have the same address (merged cells are fine). A store's own boxes must share one address; installer boxes may differ.
  • Store, Receiver and Attn: "Store Name" (or "Store", "Retailer") names the label and starts the Item Reference; "Receiver Name" (or "Receiver", "Consignee", "Ship To") is who the courier delivers to; "Attn" (or "Attention", "Contact") is the person to attend. They can be the same or different. No Receiver Name column: the receiver is taken from the address cell, else it's the store. No Store Name column: the receiver's name stands in for it. Address columns can be headed with or without "Receiver" / "Store" in front (e.g. "Receiver Address Line 1", "Store Suburb").
  • Whole address in one column: One "Address" column holding everything also works, e.g. Andrew, 27 Sirius Road, Lane Cove NSW, 2067. The parts can be separated by commas, semicolons, |, line breaks, " - " or " / ", or just spaces. The name at the front becomes the receiver (and the label's store name when there's no store column); a person and a company both given become contact and receiver. Phone numbers are ignored.
  • Receiver name only: A file with no address columns still works. Each receiver's address is filled in from the address book when it holds one address for that receiver; otherwise the consignment preview lists its saved addresses to pick from, or you type it in. Boxes still without an address are left out of the courier CSV.
  • Thumbnail: Put each row's image inside its own Thumbnail cell. Several images in one cell, or a merged Thumbnail cell, are all used.
  • Other Columns Supported: "Store Name" (or "Receiver Name"), "Quantity", "Description", "Width" & "Height" (or "Dimension"), "Address Line 1", "Address Line 2", "Suburb", "State", "Postcode", "Country", "Material" and "Notes".
{% endif %}
